# Publish runbook: `bayo-de/npc-verify-gemini` (public GitHub repo)

Status: Bayo approved publication ("Yes proceed", 2026-10-06).

Goal: publish the Verified by NPC Gemini CLI extension as the PUBLIC repo
`bayo-de/npc-verify-gemini`, add the `gemini-cli-extension` topic so the
Gemini CLI gallery crawler indexes it, and push the staged contents at
`plugins/gemini/public-repo/` (manifest at repo root).

## Non-negotiable safety rules

1. NEVER change the visibility of the private repo `bayo-de/npc-grand-fleet`. It stays private. No step in this runbook touches it.
2. The GitHub token is TRANSIENT. Never written to a file, never committed, never pasted into chat or logs. It lives in an environment variable for the session and is unset afterwards.
3. Confirm each step's output before moving on. Do not improvise new steps.

## What you need

- The staging dir: `~/workspace/grand-fleet/verified-by-npc/plugins/gemini/public-repo/`
- A GitHub classic personal access token with the `repo` scope, generated by Bayo (pasted into the terminal at execution time, never stored). Classic is recommended: repo creation is unreliable with fine-grained tokens.
- `gh` CLI installed. If it is already logged in as someone else, `gh auth logout` first.

## Step 1: take the token transiently

Bayo pastes the token when prompted. It never touches disk:

```bash
read -rsp "Paste GitHub PAT (hidden): " GH_TOKEN && echo
export GH_TOKEN
echo "$GH_TOKEN" | gh auth login --with-token
gh auth status   # confirm login as bayo-de before continuing
```

## Step 2: create the public repo and push

```bash
cd "$STG"
git init -b main
git add -A
git status --short
# Review: only the staged files. Nothing from the private monorepo.
git commit -m "Initial release: Verified by NPC Gemini CLI extension v1.0.0"

gh repo create bayo-de/npc-verify-gemini --public \
  --description "Verified by NPC for Gemini CLI. Ask 'is this real?' to check products, credentials, claims, and agents against NPC Labs verification records." \
  --source=. --push
```

`--source=. --push` creates the repo under `bayo-de` and pushes the local
commit to its `main` branch in one move.

## Step 3: set the gallery topic

```bash
gh repo edit bayo-de/npc-verify-gemini --add-topic gemini-cli-extension
gh repo view bayo-de/npc-verify-gemini --json name,url,isPrivate,topics
# Expect: isPrivate false, topics includes "gemini-cli-extension"
```

## Step 4: verify on the web

- `gh repo view bayo-de/npc-verify-gemini --web` - confirm the PUBLIC badge and that `gemini-extension.json` renders at the repo root.
- Confirm the private monorepo is untouched: `gh repo view bayo-de/npc-grand-fleet --json isPrivate` must still show `true`.

## Step 5: gallery indexing and smoke test

The Gemini CLI gallery crawler auto-indexes public repos carrying the
`gemini-cli-extension` topic (roughly daily). The listing appears once the
extension passes the crawler's validation. There is no manual submission
form; Google does not vet or endorse listed extensions.

Once indexed, smoke-test the install path from a scratch machine:

```bash
gemini extensions install github.com/bayo-de/npc-verify-gemini
```

Then run one slash command against a reachable API to confirm the helper
resolves at `~/.gemini/extensions/npc-verify/`.

## Step 6: clean up the token

```bash
gh auth logout
unset GH_TOKEN
history -c   # or close the shell; never leave the token in shell history
```

## Rollback

If anything is wrong with the new public repo (only with Bayo's explicit go-ahead):

```bash
gh repo delete bayo-de/npc-verify-gemini --yes
```

Nothing about the private monorepo is affected by any step here.

## Troubleshooting

- `gh repo create` fails with 401: the token is wrong or lacks the `repo` scope. Generate a new classic PAT.
- Push rejected / non-fast-forward: the repo name is taken or already exists. Confirm with Bayo before `git pull --rebase`.
- Gallery listing missing after 48h: check the topic is set (`gh repo view bayo-de/npc-verify-gemini --json topics`) and the manifest is valid JSON at the repo root.
- `gemini extensions install` cannot find the extension: the crawler has not indexed it yet; wait for the next crawl cycle.
